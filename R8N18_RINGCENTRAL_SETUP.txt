============================================================
1. WHAT R8N18 ADDS
============================================================

R8N18 adds the Phase 1 RingCentral-connected power dialer foundation:

- Admin creates campaigns from phone numbers already stored on uploaded accounts.
- Campaign filters include portfolio/client, assigned employee, balance, state,
  status, last-call cutoff, maximum attempts, and schedule.
- Each Co Pilot employee maps to one unique RingCentral user and extension.
- Employees use Available, Unavailable, Dialing, Connected, and Wrap-Up states.
- Compliance is rechecked by the server immediately before every call.
- One account is dialed for each available employee.
- RingCentral answer events create a Supabase Realtime screen pop.
- The exact account opens inside the employee's existing Co Pilot browser tab.
- The employee sees a connected banner and call timer.
- The next call is blocked until the employee saves a disposition.
- Calls write to the existing account activity/call-result workflow.
- Admin can start, pause, resume, and stop campaigns and see live agent states.

Voice broadcast, predictive dialing, simultaneous multi-line dialing, voicemail
recognition, and prerecorded-message delivery are intentionally NOT enabled in
R8N18. Those remain later phases after live-call and compliance testing.

3. RINGCENTRAL APP
============================================================

Create a RingCentral REST API app using JWT authentication for this fixed LIVE
team. Add only the permissions required by this phase:

- RingOut
- CallControl
- SubscriptionWebhook

Keep the app private to your RingCentral organization. Copy the app Client ID
and Client Secret for the LIVE Supabase Edge Function secrets.

IMPORTANT IDENTITY RULE

One Co Pilot employee email
=
One RingCentral user credential
=
One RingCentral extension
=
One forwarding/agent phone

Do not reuse one employee's JWT for another employee. R8N18 deliberately reads
a different user credential for each employee before placing that employee's
call.

============================================================
4. LIVE SUPABASE EDGE FUNCTION SECRETS
============================================================

Required:

RC_APP_CLIENT_ID
RingCentral REST API app Client ID.

RC_APP_CLIENT_SECRET
RingCentral REST API app Client Secret.

RC_USER_JWTS_JSON
A single valid JSON object keyed by the exact lowercase Co Pilot employee email.
Example structure only — never commit real JWT values to GitHub or chat:

{
  "collector1@example.com": "EMPLOYEE_1_RINGCENTRAL_JWT",
  "collector2@example.com": "EMPLOYEE_2_RINGCENTRAL_JWT"
}

Add all six employee emails/JWTs to the same JSON secret. Each JWT should be
restricted to the RingCentral app used by Co Pilot.

RC_WEBHOOK_VALIDATION_TOKEN
Create a long random secret used to validate normal RingCentral webhook events.
Use the same value for both new Edge Functions because Supabase project secrets
are shared by the project.

Optional:

RC_SERVER_URL
Defaults to https://platform.ringcentral.com. Use the RingCentral sandbox URL
only while testing against a sandbox app.

Single-user fallback only:

RC_USER_JWT
RC_DEFAULT_USER_EMAIL

The fallback is supported for a one-user test and only works when
RC_DEFAULT_USER_EMAIL exactly matches that employee. Do not use it to share one
RingCentral identity among multiple collectors.

Never put RingCentral Client Secret, JWTs, access tokens, or webhook validation
secrets in index.html, GitHub, Bolt, Netlify frontend variables, public/config.js,
or public/nmi-config.js.

5. DEPLOY THE EDGE FUNCTIONS
============================================================

Functions included:

supabase/functions/ringcentral-dialer/index.ts
supabase/functions/ringcentral-webhook/index.ts

The included supabase/config.toml sets verify_jwt=false for both functions.
That does not make the dialer public:

- ringcentral-dialer validates the signed-in Supabase user internally.
- ringcentral-webhook validates RingCentral's Validation-Token header.

Using the Supabase CLI from the linked LIVE project:

supabase functions deploy ringcentral-dialer --no-verify-jwt
supabase functions deploy ringcentral-webhook --no-verify-jwt

The public webhook address becomes:

https://bwvufgzbkaymffwxuuzr.supabase.co/functions/v1/ringcentral-webhook

The app creates the RingCentral subscriptions for you after mappings and user
credentials are configured.

============================================================
6. EMPLOYEE MAPPING IN CO PILOT
============================================================

In LIVE Admin:

1. Open Dialer.
2. Choose an employee.
3. Enter the RingCentral numeric API Extension ID.
4. Enter the visible extension number, such as 102.
5. Enter the forwarding/agent phone RingCentral should call first.
6. Enter the outbound Caller ID as a reference.
7. Save Employee Mapping.
8. Repeat for each employee.

The forwarding/agent phone must be configured as a valid forwarding number for
that RingCentral user. RingOut first calls the employee's forwarding number;
when answered, RingCentral connects that employee to the consumer.

After all mappings are saved:

1. Click Check Connections.
2. Confirm every mapped user reports connected.
3. Click Create / Renew User Webhooks.
4. Confirm the number of created subscriptions matches the number of enabled
   mapped users.

Webhook subscriptions are stored per employee so answer/disconnect events are
matched to the correct Co Pilot collector.

7. FIRST LIVE TEST
============================================================

Use a test consumer number you control.

1. Select one employee and one assigned test account.
2. Make sure the account contains a valid phone number.
3. Confirm no DNC, cease-and-desist, bankruptcy, deceased, attorney,
   dispute, wrong-number, blocked status, manager-review, time-window, or
   daily-attempt restriction applies.
4. Create a one-account campaign.
5. Start the campaign.
6. Employee selects the campaign and clicks Available.
7. RingCentral calls the employee's forwarding phone first.
8. Employee answers; RingCentral calls the consumer.
9. When RingCentral reports Answered, Co Pilot opens the exact account and shows
   LIVE CONSUMER CONNECTED with a timer.
10. End the call.
11. Confirm Co Pilot changes the employee to Wrap-Up and opens Call Result.
12. Save a disposition.
13. Confirm the call, account activity, campaign totals, and employee state all
    update before testing another call.

============================================================
8. PRODUCTION SAFETY RULES
============================================================

- Start with one employee and one test account.
- Never disable Compliance Guard to make a test call.
- Confirm state-specific calling windows before production use.
- Confirm caller ID, recording, consent, DNC, frequency, and debt-collection
  requirements with qualified compliance counsel.
- Do not activate voice broadcasting from this build.
- Renew RingCentral user webhooks before they expire.
- Keep each employee's RingCentral credential private and remove it immediately
  when that user leaves or loses calling access.
